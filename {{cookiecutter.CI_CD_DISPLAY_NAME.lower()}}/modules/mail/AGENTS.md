# modules/mail

- Храни здесь SMTP/IMAP-клиенты, сборку MIME-письма, шаблоны писем и работу с
  вложениями. Пакет не решает, кому и когда отправлять письмо: это делает
  сервисный сценарий.
- Настройки сервера передавай отдельными типизированными объектами, а не
  читай из окружения внутри SMTP/IMAP-клиента. У клиента должны быть явно
  видны `host`, `port`, TLS/SSL-флаг и `timeout_seconds`.

## Рабочий корпоративный пример

Эти значения работают внутри корпоративной сети. Это пример
конфигурации, а не универсальные значения для каждого нового проекта.

| Протокол | Хост | Порт | Защита | Таймаут | Аутентификация |
| --- | --- | ---: | --- | ---: | --- |
| SMTP | `cas.rt.ru` | `25` | `STARTTLS=True` | `30` секунд | Не выполнять `SMTP.login()` без явного требования задачи. |
| IMAP | `cas.rt.ru` | `993` | `SSL=True` | `30` секунд | `IMAP.login(username, password)`; username — часть логина до `@`. |

Для этого примера применяй следующие значения по умолчанию:

```text
MAIL_HOST=cas.rt.ru
SMTP_PORT=25
SMTP_USE_TLS=true
IMAP_PORT=993
IMAP_USE_SSL=true
MAIL_TIMEOUT_SECONDS=30
IMAP_SENT_MAILBOX=
IMAP_DRAFTS_MAILBOX=
```

- `IMAP_SENT_MAILBOX` и `IMAP_DRAFTS_MAILBOX` оставляй пустыми, чтобы найти
  папки автоматически. Если почтовый сервер использует нестандартные имена,
  укажи их явно этими переменными.

## SMTP

- Перед отправкой проверь непустой адрес отправителя, наличие получателей и
  существование каждого вложения.
- Создавай письмо через `EmailMessage`. Явно заполняй `From`, `To`, `Subject`,
  дату и `Message-ID`; всех получателей передавай также в SMTP envelope через
  `to_addrs`.
- При `STARTTLS=True` выполни `EHLO`, `STARTTLS` с системным SSL-контекстом и
  повторный `EHLO`. У каждого сетевого вызова должен быть таймаут.
- Преобразуй `smtplib.SMTPException` и `OSError` в понятную прикладную ошибку
  без пароля и других секретов.

## IMAP

- Используй `IMAP4_SSL` при `SSL=True`; иначе создавай обычный `IMAP4`.
- После SMTP-отправки сохрани то же MIME-письмо через `IMAP APPEND` в
  «Отправленные» с флагом `\Seen`. Черновик сохраняй только через IMAP, с
  флагом `\Draft`; SMTP в этом режиме не вызывай.
- Папку ищи строго в порядке: явное имя из конфигурации, special-use
  (`\Sent`/`\Drafts`), распространённые имена, ключевые слова. Поддерживай
  IMAP modified UTF-7 для русских названий.
- Сериализуй письмо как `message.as_bytes(policy=policy.SMTP)`, проверяй статус
  `APPEND == "OK"` и всегда выполняй `logout()` в `finally`.
- Если SMTP прошёл успешно, а IMAP-копия не сохранилась, возвращай результат
  «отправлено с предупреждением», а не отменяй факт отправки.

## Assets и тесты

- В `modules/assets` допускаются только безопасные поставляемые данные:
  шаблоны писем, тестовые вложения и публичные справочники. При запуске они
  копируются в `~/.rpa/assets`; секреты туда не попадают.
- Не изменяй тему и текст из утверждённого шаблона без отдельного правила
  подстановки. MIME-тип вложения определяй явно, например XLSX как
  `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.
- Тесты выполняй без реальных SMTP, IMAP или LDAP-подключений. Фейками проверь
  STARTTLS, отсутствие автоматического `SMTP.login()`, режим черновика,
  частичный успех SMTP+IMAP и отсутствие пароля в `repr` и логах.
